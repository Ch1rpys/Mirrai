# 手机上的原生外壳（方案与取舍）

> 这一份是 C8.8 第三部分的产出：**只写清楚两条路各自要什么、数据经过哪里**，没有做决定，也没有实现。
> 决定在用户手里：它要开发者账号、要花钱、而且和「数据不出本机」这条红线有关。做完决定之后，本文档再改成施工说明。

## 现在已经有什么

- **PWA**（可安装的网页应用）：`client/public/manifest.webmanifest`。分享菜单可以把文件交给 Mirrai（`share_target` → `sw.js` 写进独立的 `mirrai-share-inbox` 缓存 → `/share-inbox` 页面导入），快捷菜单里有「信箱」和「最近聊的」。
- **桌面外壳**：macOS 是菜单栏代理（`scripts/macos/MirraiMenu.swift`，⌥⌘M、看日志、退出时停子进程）；Windows 是托盘启动器（`scripts/windows/launcher/MainForm.cs`，Ctrl+Alt+M、缩到托盘）。窗口仍然是系统浏览器。
- 服务器还是用户自己那台机器上的那一个进程。上面的东西都只负责「打开它」。

## 手机应用是什么

手机上的原生外壳只有一种合理形态：**连到用户自己那台 Mirrai 的薄客户端**。它不跑数据库、不跑模型、不存对话——它只是另一个窗口，指向 `http(s)://<用户自己的服务器>`。

这一点决定了后面所有代价的来源：手机要能随时收到通知，而手机操作系统**不允许**应用自己常驻长连接来收通知。iOS 和 Android 都要求走厂商的推送服务。

## 两条路

### 一、PWA 加壳（不碰系统推送）

| 项 | 内容 |
|---|---|
| 需要什么 | 无开发者账号、无签名证书、无中转。把现在这份 PWA 装到主屏幕即可；要「上架」到 App Store 才需要账号，但不需要上架也能用 |
| 能拿到什么 | 分享文件进 Mirrai（已有）、快捷入口（已有）、全屏、离线开壳 |
| 拿不到什么 | **系统级推送**。iOS 的 PWA 在应用不在前台时收不到可靠通知；Android 的 Web Push 也依赖浏览器进程活着 |
| 数据经过哪里 | 不出用户自己的服务器。所有请求直达 `http(s)://<用户服务器>` |
| 代价 | 没有推送；后台任务（晚点回、到日子的胶囊、回信）只能在用户打开应用之后看到 |

### 二、真原生壳 + 系统推送

| 项 | 内容 |
|---|---|
| 需要什么 | 苹果开发者账号（个人/公司，约 ¥688/年）与 Google Play 开发者账号（一次性约 $25）；Apple 的推送证书/密钥（APNs）与 FCM 项目；两个平台的签名；如果上架，还要走审核 |
| 能拿到什么 | 应用不在前台也能收到「{{name}} 回了」这类通知；后台唤醒；分享入口与快捷入口与 PWA 相同 |
| 数据经过哪里 | **这是要拿主意的地方。** 推送必须由苹果（APNs）或谷歌（FCM）中转：消息至少会经过它们，而通知里带不带名字、带不带正文，是可以选的（C8.1 的默认就是不带正文，只写「有一条新消息」）。对话本身仍然只存在用户自己的服务器上，推送只是「去看看吧」的信号。 |
| 中转的替代 | 自己搭一个推送网关（仍要 APNs/FCM 的凭据，因为最终投递只能由它们做），或者干脆不做推送、只做「打开应用时同步」 |
| 代价 | 账号、年费、审核周期、签名与更新链路；通知元数据离开本机。这些都不是代码问题，是用户的决定 |

## 两条路的共同点

- 服务器**不新增任何出站**：手机是客户端，连的是用户自己配置的地址。推送的注册令牌由手机上传给用户自己的服务器，服务器再调用 APNs/FCM——这一步如果要登记，必须写进 `docs/egress.md`，默认关、单独开、写明发什么到哪里。
- 手机外壳里不缓存对话正文，与 PWA 的规矩一致（`/api/`、`/uploads/` 永不缓存）。
- 登录用现有的账号密码/会话 cookie，不引入第三方登录。

## 建议（待用户决定）

现阶段**不做**手机原生壳与系统推送。理由：

1. 它要的一切（开发者账号、年费、审核、中转）都不是这个仓库能在本机验证的；
2. 「数据不出本机」是产品红线，而推送的元数据必然经过苹果或谷歌——这件事只能由用户决定，不能由实现顺手决定；
3. 现有 PWA 已经覆盖「手机上打开、分享文件进来、快捷回最近对话」，缺的只有后台通知；而 WP9 的网页推送（C8.1）在桌面浏览器上已经可用。

如果要走第二条路，建议的顺序是：先决定「通知内容是否经过中转、服务器地址怎么填（HTTPS + 用户自己的证书/域名）」，再开账号、再写壳；在那之前不写任何手机端代码。

## 未验证

- 真实 iPhone / Android 上安装这份 PWA 并从系统分享菜单分享文件的体验，本机没有真机，见 `docs/exec-v6-progress.md` 的未验证清单。
- 上架、APNs/FCM 的实际流程不在本机验证范围内。
