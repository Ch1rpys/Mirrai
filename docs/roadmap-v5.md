## 〇、现在机器实际在做什么

每一轮聊天在 `server/chat/service.ts` 的 `runConversation` 里只有一次模型调用。`composeMessages` 把 `buildPromptForPersona` 的系统提示词和历史交给模型，流式路径把 token 原样吐出。提示词里已经有七层散文、已确认的判别规则、当前情绪下的不完美、记忆锚点、用户侧档案、关系事件。

行为画像（`shared/behavior-profile.ts`）里，回复间隔被加在主动开口的购买窗口之后（`sampleProactiveDelayMs`）。`proactiveRate` 和 `activeHours` 只出现在保真面板上，不参与发不发、几点发。聊天回复本身立刻流出，不读回复间隔，不读连发条数。

主动开口的额度默认是 0。打开后是 24 / 72 / 168 小时一档，从「用户上次说话」和「分身上次主动开口」里较晚的那个起算（`proactive-sweep.ts` 的 `silenceStart`）。毕业和「先缓一缓」不发。免打扰按用户时区，在写消息之前就停。消息进对话，`origin: "proactive"`，上限 120 字。窗口一到就一定会写。提示词拿到的是隔了几天、时差、用户心情、关系是否结束，再用这句提示词去检索记忆。`reachability = unreachable` 会停纪念日提醒，不停主动开口。

记忆召回（`server/chat/retrieval.ts`）按字二元组在**记忆条目**上打分。它回答「那家店叫什么」，不回答「这种时候 TA 上次是怎么接的」。

评测（`server/eval/metrics.ts` 的 `buildCharNgramModel`）用 TA 自己的字 n-gram 算似然，扣掉的那句不参与拟合。这把尺子**只在 `pnpm eval` 之后出现**，不参与挑选生成结果。三字重合率仍在报；重合率上升、本人似然下降，人会更假。`docs/eval/baseline.md` 的盲测记录表是空的。

还有一个现成的漏：`buildSystemPrompt` 在人设只要填过任意一个情绪的不完美，就会用 `mergeImperfectionDefaults` 把其余五个状态补上产品自带的通用句子。那五句是所有分身共用的。

所以施工顺序是：先让「不像」可以被指认，再从提示词里拿掉不属于这个人的句子，然后让旧回复和这一轮的动作进生成。回复延迟和拆条仍是默认关闭的开关。主动开口的闸门可以先改，不依赖生活事件写完。

## 已经定下来的做法

后面的阶段按这些决定做。改决定之前先改这一节。

1. **便宜的层默认打开，贵的层默认关闭。** 已确认的减法规则、抽样得到的言语行为、检索到的旧回复，不增加模型调用次数，蒸馏完成之后每一轮都用。四选一重排大约是四倍回复费用，延迟、沉默、拆条会改变等待感。后两样是分身上的开关，默认关。评测两条路都跑：便宜层单独一条，全套再一条。
2. **即时聊天保持一次流式回复。** `runConversation` 在开关关闭时的路径保持今天的样子：一次 `streamWithProvider`，边生成边出现。重排打开时改为并行取 N 条（N = 4）、选完再一次性交给界面，界面在这几秒里显示「在想」，不先流出一句再换掉。
3. **沉默不是默认。** 言语行为抽到「这一轮不回」时，若「按 TA 的时间」关着，就从这个人的分布里去掉沉默再抽一次。抽到沉默这件事记在本轮的调试信息里，供评测看，不给用户看一段省略号。
4. **未确认的挖掘结果不进提示词。** 与 `activeMicroRules` 同一条规矩：自动挖出的候选留在编辑器里，`verified` 之后才渲染。用户手写的条目视为已确认。
5. **旧回复是材料，不是指令。** 走现有的 `asMaterial` 围栏。与任一示范句的三字 Dice 超过 0.75 的候选直接丢掉，避免把「找示范」做成「默写示范」。评测扣下的那句不得出现在示范里，测试守住这一点（沿用 `server/eval/dataset.test.ts` 的精神）。
6. **重排不取似然最高的那句。** 先丢掉助手残渣过重、和示范过于相像、长度远离这个人的候选。剩下的里面，选长度归一化对数似然**最接近这个人真实句子中位数**的一条。平均似然最高的往往是「这个人的平均句」，认得出 TA 的常常是那种恰好属于这个人的意外。
7. **新的外发为零。** 示范句、行为计数、重排都用已经在对话里使用的那个 provider，嵌入如果要做也只走本地。不新增运营方代理。
8. **重跑蒸馏不冲掉人的判断。** `mergeUserDecisions` 已经保住确认过的判别规则和分态不完美。减法规则、被用户改过的行为分布、被标成「不像」的反馈，走同一条合并。
9. **像的是声音和判断，并且让人看得见这是重建。** 不替真人答应事情，不编记录里没有的共同记忆。`PERSONA_AI_TRANSPARENCY` 继续生效。毕业仍是北极星：这一阶段的开关不得做成「回来聊聊」的推送。
10. **主动开口买的是上限，不是时刻表。** 档位仍是 0 / 24 / 72 / 168 小时。界面写成「最多一天一条」「最多三天一条」「最多一周一条」。一次沉默只决定一次，决定由沉默起点和档位种子算出来，重启不改主意。
11. **数得出来的人，可以空过这一档。** 主动开口比例必须来自真实计数。没数过，窗口到了就发，和今天一样。数过之后，设 r 为 TA 主动开口的交换占比，参考值 0.3，这一档使用概率 p = clamp(r / 0.3, 1/3, 1)。经常自己起话头的人几乎每次都用额度；很少先说话的人大约三次额度用一次。空过不补发，下一次是再过一个完整窗口。样本够且 r = 0，这一档空过。
12. **落点用 TA 的钟点。** 用 TA 自己时区的 `activeHours`，在用户免打扰之外挑一个钟点，再加 15–90 分钟的种子抖动。回复间隔退出主动开口。用户免打扰优先：两边的钟点整段重叠时，改在免打扰结束的那一分钟送到，不再往后滑。
13. **没有材料就空过。** 没有未结事项、没有进行中的生活事件、没有一条没用过的具体记忆，而这人的开场里也没有「没什么内容的一句」或「亲近」，这一档空过，不写「在吗，想你了」。`reachability = unreachable` 时主动开口关掉。

## Phase 5 — 按 TA 的时间送出这句

仍然是开关，默认关，和重排分开。关着的时候，Phase 1–3 只影响**字**，不影响**等多久**。

| | 项目 | 落点 | 验收 | 状态 |
|---|---|---|---|---|
| F1 | 打开后，第一条气泡之前的等待从 `behaviorProfile` 的回复间隔分布里抽。没有画像或样本不足时，设置项不可开，并说明为什么 | `server/chat/service.ts` 与 `shared/behavior-profile.ts` 已有的采样 | 同一沉默期多次抽样，间隔分布贴合画像；无画像时界面说「记录不够，看不出 TA 的节奏」 | ✅ |
| F2 | 连发。用画像里的 `burstSizes` 抽样。拆分优先用模型输出里已有的换行；没有换行时按这个人的标点习惯切。切不开就一条发完，不硬切在一个词中间 | `server/chat/service.ts`；`client/src/pages/Chat.tsx` 按多条消息渲染 | 抽到 1 时永远是一条。抽到 3 时界面是三条，时间戳接近，存储是三条消息而不是一条带换行的 | ✅ |
| F3 | 这一轮动作是 `silence` 且开关打开：不写 TA 的消息。界面用产品自己的话写「TA 这会儿没回」，不生成「……」或「在忙」。下一条用户消息照常处理 | `server/chat/service.ts`；聊天页 | 测试断言这条系统说明不是 `role = assistant` 的人格消息，不进入之后的提示词当 TA 说过的话 | ✅ |
| F4 | 文本节奏并进画像：句长、换行率、问句收尾率。生成侧不另写散文，交给 E2 的长度项和 B2 的减法规则用 | `server/_core/behavior-profile.ts` | `docs/eval/baseline.md` 能多出这三行；样本不足就空着 | ✅ |

v4 的 H3（已读不回）先只做到 F3。单独的 `readAt`、撤回重发，等 F1–F3 有人真的开过开关再排，避免先做一套没人走的状态机。

人设继续是一份当前态。这一阶段只加「能够切」的最小结构，不把七层散文复制成若干份。

| | 项目 | 落点 | 验收 | 状态 |

| G1 | 记忆写上来源。`memories.messageId` 已经有列，抽取和手工创建时写入；界面能点回那条消息。没有来源的，标成用户后来写下的 | `server/chat/memory-extract.ts`；`server/db.ts` `createMemory` | 从聊天抽出的记忆能点回原句；用户手写的不假装有原句 | ✅ |

## Phase 7 — 主动开口

额度、毕业、「先缓一缓」、免打扰、消息进对话并标 `origin: "proactive"`、一条上限 120 字，都留下。应用关着时能不能推到系统通知，仍是 v4 的 D1，这里不做。

改的是这一档发不发、落在哪一分钟、开口说哪一件事。四条决定见上文「已经定下来的做法」第 10–13 条。

开场是闭集。加标签要先改这一节：

| 标签 | TA 先开口时在做的事 |
|---|---|
| `share` | 说自己的事 |
| `callback` | 接上次没说完的 |
| `checkin` | 问你一句 |
| `logistics` | 说事务 |
| `affection` | 亲近 |
| `tease` | 开玩笑 |
| `fragment` | 没什么内容的一句，例如「在吗」「干嘛呢」 |

| | 项目 | 落点 | 验收 | 状态 |
|---|---|---|---|---|
| H1 | 生活事件与未结事项先只认用户替 TA 写下的：在准备什么、答应过什么、谁说的、结束了没有。存进人设 jsonb，不在外键债还清之前加无约束的新表 | 人设编辑页；`personaData` | 能增删改。删掉之后，下一条主动消息的提示词里不再出现 | ✅ |
| H2 | 未结事项的自动候选：从记录里找「说好 / 改天 / 下次 / 等你」，必须带原句。确认前不进 H5 | 挖掘器放在判别规则挖掘旁边 | 无证据的丢弃。重跑蒸馏不冲掉已确认的条目 | ✅ |
| H3 | 开场分布只从 TA **自己先说**的历史消息里数。这类消息少于 15 条就不建分布。画像里要能分开「没数过」和「数出来是 0」：现在 `proactiveRate` 在没有 `personaSpokeFirst` 标记时会被写成 0，这个 0 不能当成「从不先开口」 | `server/_core/behavior-profile.ts`；计数放进 `personaData` 或行为画像 | 没数过的人设，H4 的使用概率是 1。样本够且比例是 0 的人设，使用概率按第 11 条可以空过 | ✅ |
| H4 | 何时发。`isProactiveDue` / `resolveProactiveDeadline` 改成纯函数：同一沉默起点、同一档位、同一画像，重启后仍是同一个决定。抽中才有送达时刻；没抽中，下一次评估点是再过一个完整窗口，中间不再调用模型。送达时刻取 TA 时区里 `eligibleAt` 之后的下一个活跃小时，加 15–90 分钟种子抖动，并且落在用户免打扰之外。不再调用 `sampleProactiveDelayMs`。`unreachable`、毕业、「先缓一缓」直接不发 | `server/chat/proactive.ts`；`server/chat/proactive-sweep.ts` | 频率 0 仍永不发。同一沉默重复计算，决定不变，模型调用次数是 0 或 1 而不是每分钟一次。回复间隔不再加进等待。活跃小时整段落在免打扰里时，送到免打扰结束的那一分钟。用户一说话，这次沉默的决定作废 | ✅ |
| H5 | 写什么。先抽一个开场（没分布就跳过这一步），再按顺序挑一件事就停：还开着的未结事项、进行中的生活事件、最近三条主动消息没用过的一条具体记忆。一件都没有时，只有分布里存在 `fragment` 或 `affection` 才允许发那种短句，否则这一档按 H4 的空过处理。`share` 没有进行中的生活事件就不可抽。关系已经结束的，从分布里拿掉指向以后一起、约时间的开场。选定的记忆直接写入提示词，不再用「你先开口、已经 N 天」这句去检索 | `composeProactiveMessage`；`collectProactiveContext` | 提示词里只有这一件事实。模型被要求不得再加第二件没提供的事。长度仍是 20–80 字，硬切 120。返回空字符串的这一档记成空过，下一分钟不再重试 | ✅ |
| H6 | 隔了几天、时差、用户心情只做染色。隔了几天只有开场是 `checkin` 或 `affection` 时可以进入正文，并且不能连续两条主动消息都靠它撑着。连续三条主动消息的开场类型不重复；材料有两件以上时，事实也不重复 | `buildProactiveInstruction` | 连续三条的类型两两不同。只有一件材料时允许事实重复，类型仍不重复 | ✅ |
| H7 | 设置文案改成上限：最多一天一条、最多三天一条、最多一周一条。说明写明空过是正常结果，暂时联系不上时不会再主动开口 | `client/src/i18n/{zh,en}.ts`；`client/src/pages/PersonaEdit.tsx` 的选项不变值，只改变文案 | 0 / 24 / 72 / 168 的存储值不变。中英两边都不再写成「每天一次」这种时刻表 | ✅ |

共同说法先不做独立词典。反复出现的怪词仍走口头禅和判别规则。应用没开着时的系统推送仍归 v4。

## 明确不做

- **不做默认的四倍生成。** 重排是开关。评测可以总是开着。
- **不把沉默做成产品的常态。** 只有「按 TA 的时间」打开才允许这一轮没有 TA 的消息。
- **不微调云端模型。** 适配器如果要做，只做本地权重，见下方暂不排期。
- **不零样本克隆音色，不生成一张 TA 的脸。** 头像如果做，只从用户已经上传的照片里选，那是 v4 的 H1，不属于这条线。
- **不把六个离散情绪改成连续向量。** 动作分布和白天/夜里的长度差，比再加一维情绪更先改变「像不像」。v4 的 H7 仍留在 v4。
- **不做群聊、推送、备份、插件市场。** 那些不改变下一句 TA 怎么说。
- **不抬留存。** 不因为分身更像了，就增加主动开口的额度，也不加「TA 想你了」这类召回。次数不会高于用户买的那一档。
- **不把主动开口做成时刻表。** 到点可以空过。空过不补发。
- **不用回复间隔决定主动开口的等待。** 回复间隔只留给 Phase 5 的「按 TA 的时间」回复。
- **不编生活。** 没有生活事件，就不允许 `share`。没有材料、开场分布里也没有 `fragment` 或 `affection`，这一档空过。

## 暂不排期：本地适配器

🔒 条件写清楚再打开：Phase 1–4 的便宜层和重排都已打开，盲测命中率仍低于 50%，且被试的理由集中在「用词」而不是「动作错了」。动作错了就回到 D 和 B，不靠权重去盖。

打开之后的约束：只在本机训练，语料是这个人的 `collected_messages`，配对是「真人句 / 通用暖味句」。云端 provider 继续负责语言能力时，就不要声称已经微调过。数据不够（TA 的回复少于大约一千条）就保持关闭，继续用重排。

## 执行顺序

```
A  指认（盲测记录 + 不像按钮 + actMatch）
└─ B  减法，含拿掉通用不完美          ← 可与 A 并行，B1 不依赖 A
   └─ C  旧回复示范
      └─ D  动作抽样
         ├─ E  重排（默认关）          ← 依赖 A4 的残渣定义与 C 的示范 id
         └─ F  按 TA 的时间（默认关）  ← 依赖 D 的 silence，以及已有的行为画像
G  来源、冲突、时期                     ← G1 可与 C 并行；G4 依赖 C
H  主动开口
   闸门 H3 H4 H7 可独立先做             ← 不依赖生活事件，也不依赖 D
   内容 H1 H5 H6                        ← H2 的自动候选确认后才进 H5
I  反馈喂回                             ← 依赖 A2、B、D
```

建议落地的第一刀是 **B1**：只改提示词怎么选不完美，不动蒸馏、不动聊天协议。它立刻去掉一批所有人共用的句子，并且有测试可守。

第二刀是 **A2 + A3**：没有「不像」的原因和 actMatch，C 和 D 做完也无法知道是哪一层在起作用。

C 和 D 是对话这一侧的主体。E 和 F 等主体有了基线再开，避免四倍费用和延迟把「句子不对」掩盖成「产品变慢了」。

主动开口的闸门（H3、H4、H7）可以在 C、D 之前落地：它改的是已有扫任务，不改 `runConversation`。内容（H1、H5、H6）等用户能写下生活事件和未结事项之后再接上。闸门先上线时，没数过开场比例的人设仍是窗口到了就发，说的仍是今天这套提示词。

## 总闸门

每个阶段合并前：

```
pnpm check
pnpm test
pnpm audit:i18n
pnpm fidelity:gate
```

动了生成或提示词的阶段，另外在本地对一个真实分身跑：

```
pnpm eval -- --persona <id> --user <id> --compare
```

比较的两列写在该阶段的说明里：B 是「通用不完美还在 / 已拿掉」，D 是「动作抽样开 / 关」，E 是「重排开 / 关」。actMatch 或本人似然没有变好，这一层就不要默认打开。重合率单独变好不算数。

盲测仍按 `docs/eval/blind-test.md`。理由集中在同一件事上，就只改那一件。
