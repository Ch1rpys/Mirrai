# Mirrai v1.4.0 — 更像 TA，也足够多

> 「让下一句更像 TA；让能用的地方足够多、足够实用。」

## 写在前面

第六阶段开工时定下的目标只有两条，原话是**「更像 TA」**和**「功能足够多且实用」**。前者不靠感觉判断，靠尺子：`pnpm eval`、判别器、盲测；后者也不靠功能列表的长度，靠的是每一项读真实记录、对着一个真实的使用场景、做完之后不用看文档就能用。这一版（第六阶段）的 164 条建议、7 条准备项和 5 条收尾项，都是围绕这两条做的。

口径先说清楚。这份草稿里说「做完」，意思是代码在、测试在、验收项逐条跑过、证据写进了[进度文件](../exec-v6-progress.md)；它**不等于**「效果已经在真实数据上验证过」。进度表用两种状态区分这件事：

- **✅ 已实现并有测试**：机器能验的部分全部验过，这一条本身不依赖真实数据和真实模型。
- **🟡 机器验收通过、效果还没量过**：开关、围栏、测量、调用次数、失败降级都有测试，但「加了它之后是不是更像 TA」需要真实聊天记录和真实模型才能量。这类条目最高只能到 🟡。

这台机器上没有真实聊天记录，没有配置任何真实 LLM provider，没有真人被试，也没有真实的外部账号和真机。所以这一版**不报任何效果数字**，不拿测试通过率冒充效果，也不编造用户反馈和发布日期。

## 一、做完并验过的

### 🗂 记录库与导入（A1–A4、C1.1–C1.7）

以前聊天记录散在几个地方：上传的文件归蒸馏读，采集器归聊天读，两边的数据还可能对不上。现在所有来源——上传文件、采集器、截图、口述、群聊——都落进同一张「记录」表，旧列不动，补上消息类型、原始说话人、来源文件、行号、附加信息（A1–A4）。

导入器覆盖 17 种内置格式：微信（TXT 两种、CSV、JSON）、QQ（TXT、MHT）、Telegram、WhatsApp、LINE、KakaoTalk、Instagram / Messenger、Discord、Android 短信、iMessage 数据库、通用逐行、通用列映射、单向文字；`.zip` 归档包自动解包（C1.1）。导入向导会自动识别格式、指认说话人（两个具名说话人且一个是 TA，另一个就是「我」；三个及以上的具名说话人里，除 TA 外都记为其他，A2–A3），先预演条数再确认；同一份文件重导只补新增的尾段（C1.2、C1.5）。

表情、图片、语音、视频、位置、链接、转账、红包、拍一拍、撤回、通话、文件、系统消息都按统一记号入库，给人看或给模型看时再渲染成字，不再丢类型（C1.3、C1.4）。来源文件可以单独删除，删掉时它带来的记录一起删；导入前可以选择脱敏（C1.6、C1.7）。蒸馏也从「解析导出的文本」改成直接读这些结构化行（A4）。

### 🏠 大厅与锚点（A5–A9）

大厅里那些把人叫回来的东西拿掉了：「每日来信 · TA 想对你说」不再出现（A5）；「想你了」换成中性的计数，推荐位也遵守分身的实际状态（A6）；连续打卡、成就徽章、对话排行从界面上移除（A7）。

「锚点」这一侧：分身自己说的话不再变成 TA 的事实，记忆抽取把「分身说过的」和「TA 说过的」分开存，审阅页按「关于 TA 的 / 关于我的 / 分身说过的」分组（A8）。危机支持的资源清单逐条核过来源，并把核对规则写成了测试（A9）。

A7 有一处没有动：`computeIntimacy` 里用到连续对话天数的那一项还是原样。它是毕业资格的输入，改了会影响已有用户的毕业判定，这一条留在「待用户决定」里。

### 🔍 读完记录与测量（WP3、B3.1、B3.2、B6.7、B6.8）

现在的蒸馏是分块的：记录切块、按层抽样、逐块抽观察卡和事实卡、只重跑新增的块；超长单条也会切成同 id 的段，不会整条丢掉（B1.1、B1.2、B1.7）。事实来自全量抽取，带合法引用和日期归一（B1.3）；动作和六态情绪回标到记录行上（B1.4、B1.5；这两条的「标得准不准」是 🟡，见第二段）。

记录不够时，系统会问一轮澄清问题，答案写回人设，重跑蒸馏不冲掉用户答过的东西（B1.6）。每条结论都能点回原话（B1.8）；人设写回前后各存一版，可以回看和恢复（B1.9）；「我」这一侧也单独读了一遍，「我」的原话不会漏进 TA 的示范（B1.10）。伤人话的识别与过滤在这一层完成，复现伤害的行默认折叠（C10.1）。

测量这一块：语气指纹（句末标点、语气词、笑、长度、emoji、从不用的词）、指纹距离、微观规则候选、记忆实体、「记不太清」的概率都有了纯函数实现，量不出来时返回空、不拿默认值填（B3.1、B3.2、B6.7、B6.8）；候选规则像不像本人（B3.5）与分态不完美草稿（B3.6）的**质量**是 🟡，见第二段。尺子这一侧另外做完了：标答按时期分层、指标压噪声、保真面板带历史、材料体检能告诉你记录够不够（B8.6、B8.7、B8.9、B8.10）。这些测量的对答案对象是一份合成夹具「小满」：每个特征都是设计出来的，测试拿量出来的结果对设计值（P0.5）。

### 🧵 生成路径（P0.3、P0.6）

聊天和评测现在走同一条生成路径：`planTurn` 负责抽动作、拼提示词，`executePlan` 负责调模型、投影、截断；评测能逐层关掉（P0.6）。分身级的开关和测量结果有了统一的位置：`personas.settings` 与 `personas.styleProfile` 两列，加字段不用再给 `personas` 表加布尔列（P0.4）。这一步是后面所有「加一层」的前提——两处各写一遍，量出来的就不是线上那个东西。

有一条硬约束被守住了：**没有第六阶段数据的分身，提示词逐字不变**。用黄金快照测试钉着，快照从建好之后没有被改过（P0.3）。

### 🕰 时间与节奏（B5.1、C5.3、C6.1、C6.2）

读和回分开了：连发三条会合成一轮，后来的消息会抢走这一轮，被抢走的那半截回复不落库；危机那一轮立即回答，不等读窗口（B5.1）。

时间胶囊到点才可读（C5.3）；主动开口和纪念日提醒是减量四级的，封存之后日历也跟着停，到日子前只留名字和日期（C6.1、C6.2）。按 TA 自己的节奏回（延迟分桶、睡眠窗、打字中、追一句）这一组是 🟡，见第二段。

这一块这一版没有 ✅ 的条目，全部是 🟡：表情包、真实语音、合成语音、照片、视频、电话模式、版式都只到「机器验收通过、效果没量」（第二段）；音色克隆和生成 TA 的脸/会动的头像决定不做（第三段）。

记录阅读器能分页翻、从搜索或原话直接定位到某条、加书签和批注、渲染贴纸、折叠伤害行；「这句 TA 说过吗」、关键词检索、我们的词典、那年今天、第一次与最后一次都在（C2.1–C2.3、C2.6、C2.7、C2.10）。「那年今天」不把整段被标成疏远或低落的那天主动摆到大厅，但在阅读器里都还在。

### 🛠 日常可用与安全（C8.2–C8.5、C8.10–C8.12、C8.14、C10.1、C10.3、C10.5–C10.7）

全局信箱与未读、收藏/置顶/引用记录、撤销与回收站、一键诊断（19 项检查）都已接上（C8.2、C8.10–C8.12）。完整备份与还原支持本地文件夹、WebDAV、S3；**先备份才能开加密**，还原只到空实例，不做合并（C8.3）。应用锁支持 PIN、通行密钥、空闲上锁（C8.4）。静态加密加密的是数据库里的文字，上传的文件不加密（C8.5）。

命令行 `mirrai` 能做测量、蒸馏、导出、备份、诊断；另有 `pnpm gate`（一条命令的总闸门）、`pnpm mcp`、`pnpm docs:*`、`pnpm i18n:hant`（C9.6）。分身包带记录、记忆、媒体导出，可以在另一台机器导入成新分身，口令加密（C9.5）。本机插件系统默认关，只支持本机目录里的导入器和通道插件（C9.7）；VitePress 文档站在（C9.7）。

Telegram、Discord、Matrix 三个通道是 🟡（缺真实 bot 账号），工具调用和群聊也是 🟡，见第二段。

## 二、做完但效果没在真实数据上量过的

这一节就是进度表里的 81 条 🟡。它们**不是没做完**：开关接好了、围栏没破、测量按预期产出、调用次数对、失败有降级，这些都有机器验收证据。缺的是同一个东西——**真实记录 + 真实模型**，有些还缺真人、真机、真实账号或真实外部服务。本机没有，所以这一版不宣称任何效果数字。

下面按主题归纳最重要的那批（每行后面是条目的编号）：

- **尺子本身**（B8.1、B8.2、B8.3、B8.4、B8.5、B8.8）：判别器能给出分数和特征归类、盲测页面能出对子并收结果、逐层消融能一行一层地跑、试镜能排候选模型、二选一能训练重排权重。还没量的是：判别器在真实评测对子上的 AUC、真人盲测的命中率、真实模型跑 50 轮后的漂移斜率、真实候选模型的排名、以及 30 次真实选择训练出的权重是否让重排更像 TA。
- **生成层的语气**（B2.1、B2.2、B2.3、B2.6、B4.1、B4.2、B4.5、B4.6）：种子轮次、固定回法、示范检索、风格样本与漂移提醒、动作邻接、动作簇、雷区、会话收尾都按测量值发出，且只在围栏里。还没量的是：加了这些段之后模型输出是不是更像 TA、会不会更少编往事。
- **更贵或要实测的生成方式**（B2.4、B2.5、B2.7、B2.8、B2.9）：两步生成、像/不像对照重写、长度上限、按调用点分工与分身采样、提示词缓存布局都能正确发出请求。还没量的是：多花的那次调用值不值、长度上限有没有把话说得更像、缓存布局对输出有没有影响。
- **重排与投影**（B3.3、B3.4）：指纹重排会按判别器和指纹选候选，标点投影会把句号、语气词按指纹改掉。还没量的是：这些确定性改动和真实模型组合之后更像还是更假。
- **专属词与称呼**（B3.7、B3.8）：确认过的专属词、按时期和状态量出的称呼史会进提示词。还没量的是：真实对话里用对了没有、会不会显得刻意。
- **动作与情绪**（B4.3、B4.4、B4.7、B4.8）：情绪惯性、冲突与和好的剧本、只接半句的减法、会话内起话头都按量出的节奏走。还没量的是：这些节奏在真实关系里读起来对不对、会不会把简单的对话写复杂。
- **标注与候选规则的质量**（B1.4、B1.5、B3.5、B3.6）：动作与六态情绪的回标、候选规则、分态不完美草稿都有确定的实现与覆盖度测试。还没量的是：真实模型标注动作/情绪准不准、挖出的候选规则像不像这个人、草稿像不像本人。
- **时间与节奏**（B5.2–B5.8、C8.1）：晚点回、延迟分桶、睡眠窗、打字中、改错字/撤回/拍一拍、追一句、通道上分条送达、网页推送都接线完成。还没量的是：真实多小时等待的体验、真实微信/飞书上的节奏、以及真机上能不能收到通知。
- **TA 的世界**（B6.1–B6.6、B6.9）：人物、喜恶、作息、知识边界、时间边界、事实核查与重写、自述账本都会进提示词或做减法。还没量的是：有真实记录时这些内容对不对、事实核查有没有减少编造、账本有没有让前后说法一致。
- **文字之外**（B7.1–B7.15 里除 B7.7 的 14 条）：表情、语音转写、原声带、语音条、韵律映射、本地 TTS、照片与人脸聚类、发照片、视频抽帧与转写、截图导入、动态、通话画像、电话模式、三种版式。机器验收覆盖的是「按测量值抽、字段发对、组件接线、失败降级」；还没量的是真实照片/录音/录像上的效果，以及真机上的听感、观感和延迟。
- **回看数字**（C2.4、C2.5、C2.8、C2.9、C8.6、C8.7）：年报、心电图、地图歌单、说明书、语义检索、示范查询都算得出来、渲染得出来。还没量的是：这些数字与本人记忆是否一致、自动找出的转折有没有意义、真机地图与打印版式好不好看、真实记录上的语义召回准不准。
- **真人与「我」**（C3.1、C3.2、C3.4、C3.6、C4.1、C4.3、C4.4、C4.6）：等待尺、排练室、读懂这一句、措辞助手、镜子、趋势与毕业条件清单、角色互换、给咨询师的摘要都做出来了。还没量的是：这些输出用在真实的人身上成不成立——尤其排练和角色互换，需要真实模型和真实记录才看得出像不像。
- **没有记录的人**（C1.8）：访谈、只导入日记和文章也能建分身，描述会标出处、不造语气。还没量的是真实访谈的提问质量，和被描述的人读起来像不像本人。
- **日常里的真机项**（C8.8、C8.9、C8.13）：原生外壳的 PWA 分享入口与桌面托盘、成本面板、场景面板都接线完成。还没量的是：真机上的菜单栏/托盘/分享、金额与真实账单是否一致、真实模型下「按那几天的语境聊」读起来顺不顺。
- **通道与生态**（C9.1、C9.4、C9.8）：Telegram / Discord / Matrix 的协议实现、工具调用、群聊都过了桩和结构测试。还没量的是：真实 bot 账号下能不能绑定和聊天、真实模型会不会主动去调那三件工具、几个分身在一个群里接话像不像。
- **安全与模型层**（C10.2、B9.3）：间接说法的危机识别加本机嵌入相似度，和关键词表并行；`logit_bias` / grammar 按能力发出。还没量的是：真实嵌入模型下危机句与无害句能不能分开（阈值现在只是经验值）、以及约束生成有没有让回复更像 TA。
- **悼念与口述**（C7.1、C7.4）：悼念守则（不谈「现在」、被问就说明自己是重建的）是提示词层，口述补全能把家人写下的说法整理成记忆。还没量的是：真实模型会不会真的不声称「在那边」、不替真人对现在做承诺，以及真实模型从口述里抽出的说法与引用在长口述上准不准。
- **没说完的话与结局**（C6.5、C6.6）：未说完的话、续写、互相读信、毕业后回访、四种毕业结局各自的信都做了围栏、承诺类过滤和不落库。还没量的是：真实模型写出来的续写和信成不成立、有没有替真人说现在怎么想。

要量这些，需要的东西已经很明确：**真实聊天记录 + 真实模型**，有些还要**真人盲测、真机、真实账号或真实服务**。缺什么、卡在哪、谁来跑，都写在[进度文件](../exec-v6-progress.md)的「未验证清单」里（按条目逐条写了缺什么、该跑的命令、谁来跑）。

如果要在自己的机器上量，建议按这个顺序来：

```bash
# 1. 把已有的上传文件补进记录表，量一遍画像（A1、3.x）
corepack pnpm mirrai measure --persona <id> --user <id>

# 2. 基线：先记下现在的数
corepack pnpm eval -- --persona <id> --user <id> --k 3

# 3. 逐层看有没有用：每一层一行；没变好的那一层关掉
corepack pnpm eval -- --persona <id> --user <id> --ablate --yes

# 4. 判别器和试镜
corepack pnpm eval -- --persona <id> --user <id> --discriminator
corepack pnpm eval -- --persona <id> --user <id> --audition

# 5. 盲测：打开 /persona/<id>/blind-test，自己做一轮，
#    再请认识 TA 的人做一轮；给朋友做的入口是 /blind/<token>
```

（具体的 `--without <层>` 用法——先 `--save` 一次开着该层的运行，再用 `--without <层>` 对比——以及每一层该配什么数据，在进度文件未验证清单的每条里都写了；`--compare` 是布尔，不接受层名。没配真实模型时这些命令只能验管道，不能看结论。）

## 三、没做的和为什么

### 决定不做的

- **B7.7 音色克隆：⛔ 不做。** 这是产品红线，写在[手册 §1.2](../exec-v6.md) 的决策表里。代替它的是两条：B7.3 原声带（把导入的语音登记成媒体、可选本机 whisper.cpp 转写、可以听/下载/收藏）和 B7.5 韵律参数（语速、停顿映射；句尾量了但不映射，因为三个 TTS 引擎都没有对应参数）。这两条也都只到 🟡，效果同样没在真实录音上量过。
- **生成 TA 的脸、让头像动起来：⛔ 不做。** 头像只从真实照片里选（B7.8），不做生成。B7.8 本身是 🟡——真实手机照片的 EXIF 和浏览器里的人脸聚类没有在真实照片上验过。

### 条件未满足的

- **B9.1 本地适配器、B9.2 浅融合：🔒 不执行。** 本阶段没有训练任何东西，只做了一条只读的解锁检查：

  ```bash
  corepack pnpm eval -- --unlock-check --persona <id> --user <id>
  ```

  它只回答「解锁条件够不够」（真实分身至少有 1000 条 TA 的文本行、请认识 TA 的人做过应用内盲测等），**即使输出 `unlocked: true` 也不代表可以做**，更不会开始训练。这台机器上只有夹具和手工造的盲测摘要，真实条件满不满足要用户在自己的机器上量。做不做在[进度文件](../exec-v6-progress.md)的「待用户决定」里，两个选项各自的代价写在那里。

### 收尾验证

- **P18.4 独立抽查：✅。** 2026-11-27 由另开的、不带实施上下文的验收会话完成：19 个工作包各抽 3 条（SHA-256 作种子）共 57 条 + 必查 A1、A2、A8、B1.1、B2.1、B2.2、B5.1、B5.2、C7.2、C8.3、C8.5、C8.11、C10.1、C10.3 共 14 条（去重后 66 条）逐条从头重跑，全部通过，没有条目降级；另外对抽样/必查集里的 38 条 ✅ 逐条试了验收清单没写到的边界情况（B3.5 全篇无记录，可核 37/38；口径见进度文件）。它留下 4 条低影响跟进项（一条文档口径、三条健壮性/守卫），同日由实现会话处理完：A1 补了偏差说明，egress 守卫不再把注释当调用点、空串备份口令改为报错、邮件主题不再带换行，三条各带回归测试。名单、结论与证据在进度文件的批次日志。**独立抽查做完不等于效果已验证**——87 条 🟡 仍然要真实记录和真实模型。
- **P18.5 交接：✅。** 交付物是这份草稿和[进度文件](../exec-v6-progress.md)开头的「给用户的摘要」（状态条数、未验证清单全文、核心命令、待用户决定全文、影响最大的偏差），与这一版一起提交。

### 明确没做的功能

- **其他界面语言。** C8.14 只做了两件事：机器转出的繁体界面，以及安全匹配认繁体输入、情绪识别加英文触发词。其他语言没有做——翻译要人来做，机器转出来的不能算完成。
- **`wechat-html` 导入格式。** 没有稳定的静态 schema 可以对着写，所以没实现；C1.1 的 17 种格式里不含它。
- **手机原生外壳与系统推送。** 只做了 PWA、macOS 菜单栏外壳和 Windows 托盘，两条路线的取舍写在 [docs/native-shells.md](../native-shells.md)；手机原生壳要开发者账号、签名和推送中转，进「待用户决定」。
- **QQ 官方机器人和企业微信通道。** 需要平台账号、应用审核或公网回调地址，本机没有，也无法核对到当前可用协议，所以没实现、设置页里也没有列；现在能用的是 Telegram / Discord / Matrix。

### 本机没条件验的（不是没做）

下面这些是「做完了但没有条件在真实环境里验」，它们也在未验证清单里，按缺的东西分组：

- **真实外部账号**：微信和飞书的真实通道、Telegram / Discord / Matrix 的 bot 账号、SMTP 发信、第三方 OpenAI 客户端、MCP 客户端、WebDAV / S3 备份目标。本机只有假 `fetch` 和 mock。
- **本机模型与服务**：Ollama 与 `bge-m3` 嵌入、whisper.cpp、piper、llama.cpp 的 grammar 服务端。没有它们，语义检索、本地转写、本机朗读、约束生成都只能验字段和降级。
- **真机浏览器与打印**：年报、纪念册、说明书的打印分页与中文字体，地图底图，可访问性与繁体的实际观感，通行密钥/WebAuthn，系统分享菜单，推送通知，电话模式的麦克风手感。
- **打包链**：Windows 的托盘与安装包、macOS 的完整打包脚本（这次只跑了 `swiftc` 编译与静态断言，没有下载 Node/PostgreSQL/Redis、签名、打 DMG 走完整条链）。
- **跨机器与大数据量**：换机器/换 `JWT_SECRET` 的备份还原（加密的凭证换实例后要重填，这一点只写在文档里没实测）、分身包跨机器导入、10 万条以上记录或上千张媒体的分身包导出耗时与内存（导出目前会把整行读进内存，见进度文件偏差 496）、100 万行上限的加密分批迁移耗时、跨机器两进程共用 Redis 的应用锁。
- **真实等待类**：真实多小时延迟回复、时间胶囊到点、30 天回收站清扫、真实群聊里的接话与消息长度。本机全部用假定时器和直接调 `sweep(now)` 验证。

### 留给你定的

进度文件的「待用户决定」里还有这些没有替你决定，每条都写了选项和各自的后果：A7 毕业资格里的连续天数要不要拿掉；C8.3 首次启动要不要直接问「新建还是还原」；C8.8 手机原生外壳与系统推送做不做；C8.5 加密账号下的家庭共享怎么处理；C9.1 QQ 与企业微信通道做不做；C9.7 插件通道要不要自己的枚举值；C9.8 群聊要不要纳入静态加密、要不要每日条数上限；B9.1/B9.2 要不要另开一个阶段做本地适配器。这一版没有替它们做选择。
